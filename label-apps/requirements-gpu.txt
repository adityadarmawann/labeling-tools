# Tambahan untuk jalur GPU. DUA tata letak yang sama-sama sah; start.sh
# memilih venv dari ISINYA, bukan dari namanya.
#
# Mesin pengembangan — venv sendiri, di samping .venv yang tetap tanpa torch:
#   python3 -m venv .venv-gpu
#   .venv-gpu/bin/python -m pip install -r requirements.txt -r requirements-gpu.txt
#   LABELAPP_OLAH=gpu ./start.sh dev
#
# Server yang harus melatih — satu venv saja, tumpukan GPU dipasang ke .venv:
#   .venv/bin/python -m pip install -r requirements.txt -r requirements-gpu.txt
#
# Kenapa dipisah di mesin pengembangan: bukan soal kerapian, melainkan BUKTI.
# Suite yang dijalankan di .venv tanpa torch membuktikan aplikasi ini benar-
# benar hidup tanpa torch; digabung, jaminan itu hilang diam-diam — cukup satu
# `import torch` di tingkat atas modul dan tidak ada yang tahu sampai ada
# pemasangan tanpa torch. Bonusnya .venv boleh dihapus-pasang ulang tanpa
# menyentuh yang satunya.
#
# Kenapa DIGABUNG di server: deploy.sh menguji venv yang dipakai prod. Dengan
# dua venv, ia menguji .venv sementara prod berjalan dari .venv-gpu — suite
# hijau di interpreter yang bukan yang dijalankan tidak membuktikan apa pun.
# Terukur bahwa satu venv GPU sanggup kedua mode: 863 tes lolos dengan
# LABELAPP_OLAH=cpu di dalam .venv-gpu (torch+cu130 jatuh ke CPU sendiri, dan
# onnxruntime-gpu membawa CPUExecutionProvider).
#
# Versinya SENGAJA tidak dipatok. Roda torch terikat ke versi driver CUDA
# mesinnya, dan mematoknya di sini membuat berkas ini salah di mesin lain.
# Yang dijamin aplikasi: kalau torch tidak ada atau GPU tidak terbaca, jalur
# CPU tetap dipakai dan alasannya dicatat di log.
torch
torchvision

# MobileSAM (pelabelan otomatis) lewat CUDA. Terukur di mesin ini, klik
# pertama pada gambar baru: 428,6 ms -> 48,1 ms (8,9x); encoder-nya sendiri
# 465 -> 37,3 ms (12,5x). Ini latensi yang benar-benar ditunggu orang saat
# melabeli, bukan pekerjaan latar.
#
# PENTING: onnxruntime-gpu dan onnxruntime menyediakan modul `onnxruntime`
# yang sama dan TIDAK boleh terpasang berdua — ketika keduanya ada, yang
# terpakai bergantung urutan pemasangan. requirements.txt memasang
# onnxruntime (jalur CPU), jadi di .venv-gpu ia harus dibuang lebih dulu:
#
#   .venv-gpu/bin/python -m pip uninstall -y onnxruntime
#   .venv-gpu/bin/python -m pip install --force-reinstall --no-deps onnxruntime-gpu
#
# --force-reinstall itu bukan kehati-hatian berlebih: uninstall onnxruntime
# ikut menghapus berkas yang dipakai bersama onnxruntime-gpu, dan sesudahnya
# `import onnxruntime` berhasil tetapi modulnya kosong —
# "module 'onnxruntime' has no attribute 'SessionOptions'".
onnxruntime-gpu

#
